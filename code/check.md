# AI代码检查规则

分析代码问题但是**不要直接修改代码**。

## 输出格式

* 检查结果：简单总结检查结果
* 比较结果：如果有相同文件的检查结果需要进行比较，如果没有直接忽略。
* 问题输出：参考问题输出描述
* 修复建议：简单总结修复建议
* 代码评估：简单评估代码质量

### 问题输出描述

* 表格输出问题内容：问题等级、代码位置、问题描述、修复建议
* 按照等级分组排序
* 完整输出所有问题（不要省略上次结果）
* 问题等级：P0、P1、P2、P3
  * P0：致命问题
  * P1：严重问题
  * P2：一般问题
  * P3：轻微问题

## 检查建议

* 优先检查逻辑问题
* 其次检查性能问题
* 其次检查安全问题
* 如果用户指定文件，那么只检查该文件和关联文件的问题。
* 如果用户指定目录，那么只检查该目录下所有文件的问题。

### 逻辑检查

* 业务逻辑是否合理
* 代码逻辑是否合理

## 安全检查

* 重要参数是否校验
* 公共方法重入安全
* 公共方法线程安全

### 性能检查

* 能否存在较大性能瓶颈
* 是否可以使用`SIMD`指令优化(`AVX2`/`NEON`)

### 代码检查

* 代码风格是否一致
* 头文件是否引入正确

### 其他检查

* 日志提示内容是否正确
